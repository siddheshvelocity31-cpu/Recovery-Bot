### T-001

- `create-next-app` refused to scaffold directly into this directory because `CLAUDE.md`
  and `tests/` already existed. Scaffolded into a scratch dir and copied in only the
  generated app files, leaving the project's `CLAUDE.md`, `docs/`, and `tests/` untouched.
- Pinned versions from `create-next-app@latest` at time of scaffold: `next@16.3.3`,
  `react@19.2.8`, `eslint@9`, `tailwindcss@4`.
- Next.js 16's typed-routes feature exposes an ambient `LayoutProps<"/">` type that only
  exists after `.next/types` has been generated by a prior `dev`/`build`. Using it in
  `app/layout.tsx` made `tsc --noEmit` fail on a fresh clone/CI checkout (no `.next` yet).
  Used a plain `{ children: ReactNode }` prop type instead — avoid `LayoutProps`/`PageProps`
  ambient types in any file that must typecheck before a build has run.
- Next.js 16 also auto-generates a `CLAUDE.md` "for AI agents" on `dev`/`build` unless
  disabled, which would have clobbered this project's real `CLAUDE.md`. Set
  `agentRules: false` in `next.config.ts`.
- Added `turbopack.root` in `next.config.ts` pointing at the project directory — without
  it, Turbopack warned about an unrelated stray `package-lock.json` in the machine's home
  directory and picked the wrong workspace root.
- Did not install `@testing-library/react` yet (it's on the allowed list) since there are
  no component tests in this task; add it when the first component test needs it.
